CODE REVIEW: bp_tracker.py
=============================

CRITICAL BUGS
=============

1. Line 297: sys.exit() misuse
   Current: sys.exit(1, "Cannot find {}".format(args.file))
   Problem: sys.exit() only accepts an integer exit code, not a message
   Fix: print("Cannot find {}".format(args.file)); sys.exit(1)

2. Lines 317-320: Crash on empty results
   Problem: If no results match date range, format_report() calls get_last()
   on empty lists, causing IndexError
   Fix: Check if results list is empty before calling format_report()

3. Line 131, 133: Unpacking None causes crash
   Problem: get_labels() returns None for out-of-range values, but code
   unpacks it expecting a tuple
   Fix: Either handle None or ensure values are always in range


ROBUSTNESS ISSUES
==================

4. Result.__init__() (lines 51-59): No input validation
   Problems:
   - No check if line_data has at least 3 elements (will crash on malformed data)
   - No validation that values are reasonable (negative BP, systolic < diastolic)
   - No validation of timestamp format
   - ValueError on non-numeric input gives cryptic error

   Improvements:
   - Add try/except with clear error messages
   - Validate len(line_data) >= 3
   - Validate systolic > diastolic
   - Validate positive values (systolic 1-300, diastolic 1-200, pulse 1-300)
   - Validate timestamp format with regex or datetime.strptime()

5. average() (line 103-105): No handling of empty list
   Problem: Division by zero if empty list passed
   Fix: Check len(lst) > 0 or raise ValueError with clear message

6. results_from_file() (lines 89-100): Limited error handling
   Problems:
   - FileNotFoundError caught in get_data() but other exceptions
     (PermissionError, IOError) are not
   - If any line fails to parse, entire operation fails

   Improvements:
   - Log/warn about unparseable lines instead of crashing
   - Handle permission errors gracefully
   - Consider returning (results, errors) tuple

7. add() (lines 76-86): Modifies input argument
   Problem: args.add.append(timestamp) modifies the input list
   Fix: Create a copy: this_report = list(args.add)

8. check_file() (lines 108-122): Edge case with empty dirname
   Problem: If file is "bp_numbers.txt" (no directory),
   os.path.dirname(file) returns "" which may fail
   Fix: Use os.path.dirname(file) or "." for current directory

9. Date validation missing in main (lines 302-310)
   Problem: No validation that date arguments are valid YYYYMMDD format
   Fix: Validate date format (8 digits, valid month/day)

10. No data validation on add (-a argument)
    Problem: User can add nonsensical values (999/999/999)
    Improvement: Validate ranges and warn if unusual

13. Consolidate get_label() and get_labels()
    Problem: Nearly identical code, only difference is return value
    Solution: Have get_labels() call get_label() or vice versa
    Example:
        def get_labels(num, scale):
            label = get_label(num, scale)
            if label is None:
                return None
            for group in scale:
                lower, upper, lbl = group
                if lbl == label:
                    return lower, upper, label
